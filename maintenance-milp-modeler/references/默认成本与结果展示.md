# 默认成本口径与结果展示

## 默认行为

用户没有指定目标时，默认采用**经济成本最小化**。用户没有指定测试场景时，默认使用基座01；两项默认都必须在结果中以一行简短说明展示。若关键成本输入缺失，先使用项目已确认的默认参数；没有确认参数时标为待补数据，不得用零悄悄代替。

第一阶段默认经济成本包括：

| 成本项 | 默认口径 | 基座/项目默认值 |
|---|---|---:|
| 船舶租赁 | 按窗口首项开工到末项完工覆盖的北京时间自然日计费，等待和转场照计 | 12,000 元/船·天 |
| 维修人工 | 实际维修人时计费 | 150 元/人·小时 |
| 备件 | 每任务固定备件数量×部件维修包单价 | 部件库价格 |
| 停机发电机会损失 | 故障降额或维修停机时段的预计少发电量×预测电价 | 需要风速、功率曲线、电价 |
| 动员、额外燃油、等待/转场人工 | 仅在参数非零或用户启用时计入 | 默认0 |

维修期间整机停机，故障尚未维修期间按部件/严重等级剩余出力系数计算；同一时段不得重复计算同义损失。成本口径、单位、时间范围和数据来源记录在结果元数据中。现金预算与含机会损失的经济成本是不同概念，用户说“预算”时仍需确认口径。

## 两套人工直觉基准与节省

默认使用两套人工直觉基准，而不是另一个“经济成本单目标基准”。两套基准都遵守海事窗口、安全、库存、作业线、人员和每日工时等硬约束，但不考虑电价、风速经济性或复杂多目标权衡：

1. **严重性优先基准**：按高→中→低严重等级排序，在临近可用窗口内尽量安排并完成；同等级内按告警先后或固定任务编号排序。它回答“只按严重程度头痛医头，最早什么时候能修完”。
2. **低风速窗口优先基准**：不区分严重等级，按窗口内可作业时段的风速从低到高排序，优先把低风速时段排满；风速相同时按窗口起始时间和固定任务顺序排。它回答“只看哪个时段风小，先把低风速时段用满”。

两套基准如果在硬约束下无法形成完整排程，必须报告无完整基准，不能虚构完成时间。推荐方案分别计算：

`人工基准经济成本 - 推荐方案经济成本`

并报告节省比例、完成任务数差异和最晚完工时间差异。两套基准不能合并成一个数字，也必须使用相同输入、硬约束和成本口径。

## 用户首屏

普通请求的首屏只回答：

1. 推荐哪个窗口、日期和建议船舶租赁天数；
2. 该窗口修哪些任务（风机、部件、严重等级、任务数）；
3. 推荐方案总成本、相对两套人工基准分别节省多少；
4. 有哪些任务未安排，以及是否是库存、窗口、海况、能力还是数据缺失造成；
5. 一行假设说明：例如“默认基座01，合成数据；默认经济成本口径”。

详细排程、逐任务开完工时间、费用分项、库存收发、输入来源、模型目标、候选方案、不可行诊断和审计信息作为附件/展开项。不要在首屏先倾倒完整告警表、参数表或求解日志。

## 推荐输出模板

```text
推荐窗口：窗口01（日期）
建议维修：X项——风机…/部件…（按窗口分组）
预计总成本：¥…
相对严重性优先基准：节省¥…（…%）
相对低风速窗口优先基准：节省¥…（…%）
未安排：X项；主要原因：…
口径：默认基座01、合成数据；默认经济成本=船租+人工+备件+停机/降额发电损失。

[展开：逐任务排程] [展开：成本明细] [展开：库存变化] [展开：模型与数据审计]
```

没有真实求解结果时，必须明确标注“演示/基线/未重新求解”；已有审计排程不能直接称为本次成本优先推荐。

# 四种目标的固定建模契约（第二版）

适用于第一阶段检修项目。规范源为同目录 `四种目标模板.json`，版本2.0；确定性生成入口为 `scripts/objective_templates.py` 的 `apply_objective_template`。大模型只选择模板、目标模式、绑定真实已校验的数据与候选、填写用户明确覆盖值，不自行改变指标定义。

## 目标模式

两种模式共享同一组安全、许可、库存、资源、期限和服务约束。

- `分层`（默认）：严格按对应策略表中的目标次序求解；前一层达到已证明的最优值后才优化下一层。适合“高风险必须优先于成本”这类不可交换的优先级。
- `加权`：将所选指标按各自有限变量边界映射至0—1区间，最大化指标转成损失方向，再用一个加权和目标求解：`min Σ w_j × normalized_loss_j`。适合用户接受成本、完成量、严重度和时间之间的折中。权重是相对偏好，不是百分比承诺；四策略有版本化默认值，也可由用户完整覆盖当前策略的权重。自定义权重须列出该策略的全部指标；不参与的指标写0。

标准化范围用线性表达式在已声明变量上下界上计算，属于安全的有限范围但可能比可行域实际范围宽。模型来源记录权重、范围、模式和版本；权重必须有限、非负，至少一个为正。分层模式不接收权重。加权目标允许权衡，所以高风险完成数量不保证优先于成本；法定期限、已承诺任务和用户明示的必修要求必须用硬约束表达，不能只靠权重。

组合偏好时只能使用所选注册模板已有的指标。`成本最低优先`模板没有严重度指标；若用户要成本与严重度折中，应使用`高风险优先抢修`的加权模式，或提出新版本扩展，不能静默给成本模板塞入高严重度目标。当前高风险加权默认值中，严重度完成数合计权重0.80，成本权重0.15；不能将其描述为成本主导。如果用户要求成本占主导、同时保留严重度偏好，需确认完整权重，不从自然语言自行猜比例。成本策略的自定义权重需要列出四项指标；不使用的时间指标显式设为0。

## 四种含义与固定优先级

|模板|依次优化的固定目标|
|---|---|
|高风险优先抢修|最多完成高严重任务→最多完成中严重任务→最多完成低严重任务→高严重任务最早完工时间和→中严重任务最早完工时间和→低严重任务最早完工时间和→最低总经济成本→最早最后完工时间|
|成本最低优先|最低总经济成本→最多完成任务→最早最后完工时间→最小完工时间和|
|最短完成优先|最早最后完工时间→最小完工时间和→最低总经济成本→最多完成任务|
|检修最多器件优先|最多完成部件维修任务→最多完成高严重任务→最多完成中严重任务→最低总经济成本→最早最后完工时间→最小完工时间和|

箭头表示上一层最优值先锁定，再优化下一层，不是加权平均。高风险在本项目仅指告警严重等级，不擅自引入故障概率或人民币风险罚金。最短完成是最小化最后一项的实际完工时刻，不是最小化工时之和、平均工时或船租天数。器件数按唯一部件维修任务计，一台风机两个不同部件是两项，不按风机台数计。

## 共同服务和硬边界

应用模板前必须给出共同必修任务编号集合，或正整数的最低完成任务数量。不能通过所有任务不选获得“成本最低”或“最短完成”。业务已明确所有任务必修时，不得改为只修一项；最低完成数也不能替代已存在的正式维修期限。

四种方案比较使用相同的输入数据、候选、任务范围、必修集合、最低完成要求、历史批准占用和时间域。安全、海事许可、库存、作业线、人员上限和期限等原约束全部保留。模板只增加标准选择规则、服务下限和完工指标，不删除原约束。共同必修条件本身冲突时返回不可行，不因切换策略自动删任务或顺延期限。

允许部分完成的诊断方案是另一个显式模型模式。调用者需要声明其中哪些任务允许不安排；不得把正式必修集合静默清空。已批准和已开工承诺保持不变。没有待修任务时直接报告无需新增检修，不用伪造一项服务要求。

## 线性形式

对任务i的已验证完整维修候选k，绑定已声明二元变量 `x[i,k]`。`t[i,k]` 是候选实际完工分钟（同一时间基点的固定数据，已包含海况停工历时）。候选由业务编译器先检查告警接收时间、库存、窗口和安全条件；目标生成器不替代这些检查。

- 完成数：`N = Σ x[i,k]`，每任务有 `Σk x[i,k] ≤ 1`；必修任务为等号1。因此同任务多个候选不会重复计数。
- 各严重等级完成数：仅对相应等级的任务求和，不用LLM自定严重度权重。
- 各等级完工时间和：`Σ t[i,k] × x[i,k]`，未选任务贡献0；各等级完成数已被前级锁定后，这才表达同等完成量下的尽早维修。
- 最后完工：增加有限有界连续变量 `T`，`0 ≤ T ≤ H`；对每候选加入 `t[i,k] × x[i,k] ≤ T`，再最小化T。H取当前确定的时间域，不猜大M。
- 成本：直接绑定业务编译器产生且通过线性校验的总经济成本表达式，包含发电收入差、船租、人工、材料及明确启用的其他费用。生成器不猜费用系数。

生成器返回标准ModelSpec，附模板编号、版本、目标模式、服务约定；加权模式另记录权重及标准化范围。用通用求解入口求解；分层模式前级未证最优时停止并报告已完成层级，加权模式报告单一合并目标及独立约束复核。浮点求解按已披露容差复核。相同输入及版本生成相同目标和约束，不增加时间戳等随机字段。

## 调用接口

```python
model = apply_objective_template(
    base_model, '成本最低优先', tasks, total_cost_expression,
    horizon_minutes=35 * 24 * 60,
    required_tasks=required_ids,
    minimum_completed=minimum_count,
    objective_mode='加权',
    weights={'总经济成本': 0.6, '完成任务数': 0.4,
             '最后完工时间': 0, '完工时间和': 0},
    version='2.0',
)
```

tasks每项包含中文字段“任务编号”“严重等级”“候选”；候选包含“变量编号”“完工分钟”。所有候选选择变量必须已经声明为二元变量，且不能跨任务重复使用。没有可行候选的必修任务生成空和等于1，由求解器明确判冲突；不会被略去。

基础模型中可以保留日租等辅助变量。其完整定义、成本系数、作业和库存行由业务编译器负责。四模板生成器不等于100台全场成本编译器已经完成。

## 验证与版本

`tests/test_objective_templates.py` 使用同一有限资源、最低完成一项的四任务数学例。四模板分别选择高严重任务、最低成本任务、最早完成任务、最多任务组合，另检查模型生成一致、缺服务要求阻塞、必修保留及冲突不被隐藏。该例验证目标语义，不是四策略全场对比结果。

同一数据上四策略可能选出相同方案：例如所有任务都必修，完成数量已固定。固定目标也不意味着多个同优解时排程唯一；如需固定排列，应另设经过版本管理的确定性最终规则，不能伪称当前已经保证唯一。

用户选择标准策略不再重新澄清其已定义含义；用户提出“最短完成改为平均等待最短”等新解释时，应显式提议新模板版本，不悄悄修改2.0。版本更新要重跑目标行为与既有回归，再同步安装副本。

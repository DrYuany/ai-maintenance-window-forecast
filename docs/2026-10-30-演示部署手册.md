# 演示部署手册

> 目标：让人在浏览器里摸到这个产品，不需要装任何东西，不花一分钱。
> 边界：这是**演示**，不是生产。数据和参数是模拟的，别拿它下真实作业令。

## 一、这套方案长什么样

```
体验者浏览器
    │  https://xxx.r6.cpolar.top/?k=口令
    ▼
cpolar 隧道（境内节点，免费版够演示）
    │
    ▼
你本机 127.0.0.1:8010
    ├── /api/*  → FastAPI（Agent + 求解器）
    └── /*      → build/index.html（前端，单文件 2.5MB 全内联）
```

**关键设计：前后端同源，只开一个端口。** 前端 `API_BASE_URL` 默认空字符串，自动走同源，所以不用配任何地址、不用处理跨域、隧道换地址也不影响页面。

> 隧道必须用**境内节点**。2026-11-01 实测：cloudflared（Cloudflare 免费隧道）在这台机器所处的网络下不可用——52MB 客户端下载只有 20KB/s 且多次中断，serveo 隧道虽然握手成功，但从公网拉首页 28 秒只传出 160KB（5.8KB/s）就被重置。同样时刻，国内站点下载能跑到 3.5MB/s。瓶颈在跨境链路，不在代码。

为什么不让后端也上云：求解要 60–300 秒、要读写 `data/` 和 `product-output/`、要 SQLite 持久化。免费 serverless 三条全踩雷（函数超时、无持久盘、512MB 内存配 0.1 CPU）。放自己机器上，这些都不是问题。

## 二、启动

### 最快：一条命令

先用一次 cpolar：解压 `scripts/bin/cpolar-setup.zip` 里的 `cpolar_amd64.msi` 双击安装（一路默认），到 [cpolar.com](https://www.cpolar.com) 注册，控制台复制 authtoken，执行一次：

```bash
cpolar authtoken 你的令牌
```

之后每次演示只要：

```bash
python scripts/demo_reset.py     # 换人之前恢复出厂
python scripts/demo_public.py    # 起服务 + 起隧道 + 自检 + 打印邀请链接
```

`demo_public.py` 会自己起后端、等健康检查通过、拉隧道、从公网回访一次确认别人能打开，然后打印带口令的邀请链接。Ctrl+C 一起停。

下面是手动分步，排障时用。

### 1. 恢复出厂数据

```bash
python scripts/demo_reset.py
```

会做两件事：把 `data/phase1-demo/` 恢复到 git 里的版本（检修单、出海清单、执行反馈回到空表）、删掉 `data/agent.db`（对话历史、方案版本清空）。

**换下一批人体验之前，重复这一步。**

### 2. 起服务

```bash
python scripts/demo_serve.py
```

会打印：

```
  本机打开   http://127.0.0.1:8010/?k=x7k2m9
  访问口令   x7k2m9
  健康检查   http://127.0.0.1:8010/api/health
```

口令可以自己指定：`python scripts/demo_serve.py --code demo2026`。

没设口令时后端行为和平时完全一样（不加任何拦截），所以这个脚本也能当普通开发服务器用。

### 3. 开隧道

另开一个终端：

```bash
cpolar http 8010
```

它会打印一行 `Forwarding https://xxxx.r6.cpolar.top -> http://localhost:8010`。**把口令接上去就是邀请链接**：

```
https://xxxx.r6.cpolar.top/?k=x7k2m9
```

> 免费版的随机域名**每次重启隧道都会变**。要固定地址，在 cpolar 后台保留一条二级子域隧道（免费版可保留 1 条），或升级付费版绑自己的域名。
>
> 不要再用 cloudflared / serveo 这类境外隧道。见第一节末尾的实测数据：客户端下不动，隧道通了也只有 5.8KB/s。

## 三、口令这道门挡什么

`backend/app/main.py` 里加了 `_attach_demo_guard`：

- 第一次带 `?k=口令` 访问，后端种一个 7 天有效的 cookie，之后正常用
- 没有 cookie 也没有口令：页面看到一张提示页，`/api/*` 返回 403
- `/api/health` 免检，方便隧道和监控探活
- 环境变量 `DEMO_ACCESS_CODE` 为空时，这套逻辑整体不启用

它挡的是扫描器和误入的陌生人——**不是真正的身份认证**。别把真实数据放进来。

### 免费 10 轮，之后用自己的密钥

口令门的另一半：**给多少、谁来付模型费**。

| 行为 | 结果 |
| --- | --- |
| 前 10 轮对话 | 用服务端配置的 `MINIMAX_API_KEY`，访客不花钱 |
| 第 11 轮 | 返回 402，前端弹窗要求填自己的 DeepSeek 密钥 |
| 填完密钥 | 先花 1 个 token 试一次，通了才保存；之后每轮都用这把 |
| 忘了存哪 | 只存在浏览器 localStorage，清掉就等于没填 |

三个配置项，都在 `.env.local` 或启动命令里：

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `DEMO_FREE_TURNS` | 0（不限额） | 每个访客的免费轮数。`demo_serve.py` 默认写 10，部署包写 10 |
| `DEMO_DAILY_TURNS` | 300 | 全局每日总轮数。防止有人换浏览器刷额度把密钥刷空 |
| `MINIMAX_API_KEY` | 无 | 免费轮次用这把；访客自带密钥时不碰它 |

计数按访客走：前端 localStorage 里一个随机 ID 随请求带上，服务端拿它记在
`demo_turn_usage` 表里，顺带记一份全局的 `demo_turn_daily`。

**这套东西是"劝退"，不是"门锁"**：换个浏览器、清个 localStorage 就能再拿
10 轮。真正兜底的是 `DEMO_DAILY_TURNS`——把每天的总消耗封在 300 轮以内，
一把钥匙最多也就花这么多。要更硬就得上账号体系，那是另一个工作量。

本地演示想不限轮次：`python scripts/demo_serve.py --free-turns 0`。

## 四、版本管理

### 当前演示版本的标记

```bash
git tag -n1                     # 看所有标记
git checkout demo-v1.0          # 回到这一版
```

### 为什么 `build/` 不在版本库里

`.gitignore` 里排除了 `build/` 和 `product-output/`，因为它们是可再生产物。复现某个演示版本的正确姿势：

```bash
git checkout demo-v1.0
npm ci                # 严格按 package-lock.json 装依赖
npm run build         # 重新生成 build/index.html
python scripts/demo_reset.py
python scripts/demo_serve.py
```

`npm ci` 而不是 `npm install`：前者严格按锁文件，后者会升级小版本，可能导致界面和当初不一样。

### 每次改完演示相关代码

```bash
git add -A
git commit -m "demo: ..."
git tag -a demo-v1.1 -m "演示版 1.1：..."
```

## 五、给体验者的三分钟引导

把这段话直接发过去，比让人自己瞎点有效得多：

> 1. 先看首页的告警列表，现在挂着的任务都在这儿
> 2. 在对话框问：「现在有哪些告警？」——它在读台账，不是编的
> 3. 再问：「船租涨两成，重新算一遍」——看成本怎么变
> 4. 试试：「3 号部件的货晚到三天」——这种带主语的改动它能接住
> 5. 最后点「下发检修单」，再审批通过，看任务状态怎么走
>
> 注意：这轮数据是模拟的，数字别当真，看流程。

如果想演示「排不下」这件事，可以问：「每天只能工作 8 小时」，会看到降级和部分方案的处理。

## 六、常见问题

**Q：打开是空白页 / 一直转圈**
先直接访问 `http://127.0.0.1:8010/api/health`，返回 `{"ok":true,"demo":true}` 说明后端活着。空白多半是隧道地址拼错了，或者 `?k=` 后面的口令不对。

**Q：提示「演示口令无效」**
cookie 过期（7 天）或者换了浏览器。重新用带 `?k=口令` 的完整链接打开一次就行。

**Q：点求解一直不出结果**
求解是异步任务，界面上有进度。今天这份数据大约 12 项待安排，45–60 秒出结果。如果超过 3 分钟没动静，看后端终端的报错。

**Q：`scripts/demo_reset.py` 报「删不掉 agent.db」**
后端还在跑，Windows 锁住了文件。先 Ctrl+C 停服务，再重置。

**Q：`product-output` 越来越大**
每次求解写一套 pbtxt + json + html + csv，现在历史累计 700MB+。演示不依赖它，直接删掉整个目录即可，下次求解会自动重建。

**Q：隧道地址变了，之前发给别人的链接失效了**
免费版随机域名每次重启都换，只能重发。要固定就在 cpolar 后台保留一条子域隧道。

**Q：`demo_public.py` 报「没找到 cpolar」或「还没登录」**
先装 `scripts/bin` 里的 msi，再 `cpolar authtoken 你的令牌` 执行一次。装完新开一个终端，让 PATH 生效。

**Q：别人打开很慢**
单文件前端 2.5MB（gzip 后约 1.2MB，但没开压缩中间件），免费隧道带宽有限，首屏几秒到十几秒都算正常。要快就换付费带宽，或者把前端拆包让浏览器缓存生效。

## 七、这套演示能证明什么，不能证明什么

**能证明**：自然语言改排程是真的能跑通、目标是真在求解器里算的、闭环（下发—审批—反馈）是通的、界面是有产品感的。

**不能证明**：数据是真的、参数是业务确认过的、能扛并发、有权限体系、能接现场系统。

`PRODUCT_READINESS.md` 里那四条仍然成立：接现场接口、参数由业务确认、部署运维体系、逐任务反馈。**演示不改变这四条**，只是让人先看见东西长什么样。

# 注册表驱动的意图识别（槽位说明书）

> 日期：2026-10-29　状态：已完成并验证　分支：feat/registry-driven-schema-prompt

## 问题

用户反馈："我说'人员能加班，每天能修12小时'，大模型肯定能翻译成'每天维修时间 ≤ 12 小时'
的槽位，但我们没实现。现在是不断加规则，加到什么时候？换个说法'让人猛干'又漏了。"

根因有两个：

1. **LLM 拿不到槽位清单**。手写的 `_PARSE_SYSTEM` 只列了 11 个约束原语和 2 个参数例子，
   而注册表里有 16 个原语、51 个可改参数、6 张数据表。模型不知道「每日有效维修上限」
   这个槽位存在，自然填不出来。
2. **规则层是唯一的覆盖手段**，于是不断堆正则，长尾永远补不完。

## 方案

注册表从"只给校验器用"变成"同时给 LLM 当说明书"，LLM 成为主解析器，规则层降级为
单约束快速通道（省成本省延迟，不做覆盖）。

### 分层注入（控制 prompt 体积）

| 层 | 内容 | 体积 |
|---|---|---|
| L0 目录 | 51 个可改参数一行一个（名称+单位+取值约束） | ~2k 字符 |
| L1 详述 | 按本轮话术检索 top-6 + 10 个高频槽位详解 | ~1k 字符 |
| L2 固定块 | 原语 16 + 数据字段 6 表 + 实体 7 + 输出契约 | ~1.5k 字符 |

合计约 4k 字符（全量详述约 6.3k，手写提示词 1.8k）。

### 四件事

1. **有什么**：实体清单 + 6 张数据表
2. **什么能改**：51 个可改参数 + 16 原语 + 5 目标
3. **改成什么格式**：DSL 字段/单位/取值约束 + 输出契约
4. **现在是什么状态**：快照清单（只有实体名，没有数值）+ 当前方案 + 待确认变更 + 最近 3 轮

1–3 是系统提示词（静态，注册表自动生成）；4 是上下文（每轮动态拼）。

### 配套修复

- **门控空转**：`parameter/strategy/data_patch` 三个路由实测旧规划器一条都接不住
  （`is_planning_request` 全 False），继续截走只会退化成自由聊天。现在只保留
  确定性可判的路由（not_change/reject/clarify/batch），其余交给 LLM。
- **复合句静默丢失**：规则层原来 `return` 第一个匹配，复合句丢掉后面的约束。
  现在收集全部匹配，多于一个不同约束就整体交给 LLM；用「最长匹配 + 跨度包含剔除」
  处理「不允许跨天暂停」命中「允许跨天暂停」子串的问题。
- **参数 op 归一化**：模型常省 `op`，解析层补 `"="`（只补省字段，不猜语义）。
- **列表型参数**：校验器原来把数组当数字校验直接拒绝，现支持列表值。

## 实测结果

对抗槽位评测集（`eval_cases/adversarial_slots.jsonl`，70 条）：

| 配置 | 准确率 |
|---|---|
| 旧手写提示词（基线） | 24.3%（17/70） |
| 注册表槽位说明书 | **94.3%（66/70）** |

221 条提问库（真 LLM）：门控 99.5%，DSL 类型 100%。后端测试 282 通过。

## 已知局限

- 复合句里 LLM 仍会漏项（"任务001和任务003必须修"只输出 must 任务001）——
  需要句子拆分 + 结果合并，属后续工作。
- 时间限定的数据修改（"未来三天电价上涨20%"）不能用全局倍率顶替，现在强制 clarify。
- 相对量缺基准（"顺延两天"）仍走 clarify。

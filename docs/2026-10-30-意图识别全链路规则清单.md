# 意图识别：全链路规则清单（截至 demo-v1.5）

这份文档把"一句话进来以后，到底被哪些规则判断过"逐条列出来。不概括。

代码位置：

- 上游门：`backend/app/core/agent_runtime.py:571` → `planning_intent.py::is_planning_request`
- 漏斗主体：`backend/app/core/dsl/llm_parser.py::_parse_core`
- 旧编译器：`backend/app/core/planning_intent.py::compile_detailed`

---

## 0. 真实结构：不是一条八层直线，是"先分叉，再漏斗"

```
用户一句话
   │
   ├─ 门 is_planning_request？
   │     ├─ 真 ──→ 旧规划器（纯正则，compile_detailed）──→ 出方案
   │     │          ↑ 大模型不参与，DSL 六层一步不走
   │     └─ 假 ──→ DSL 漏斗（下面 1~8 层）
```

这道门是**互斥分叉**，不是"漏斗里的一层"。它判真的后果是：整句交给正则，
`_parse_core` 的规则层、向量层、大模型层全部不执行。

`_try_dsl_parse` 只在门判假时被调用（`agent_runtime.py:572 if not planning_request:`）。

## 1. 层 0（门）：`is_planning_request`

按代码执行顺序，五段判据：

### 1.1 explicit_action —— 明确的动作诉求

7 个词组：
`重新排程` `重新安排` `生成方案` `帮我排` `调整排程` `开始求解` `重新求解`

1 条正则：
```
(?:排|生成|出|做|算)\s*(?:一版|一个|一份|个|版)?\s*(?:方案|排程|计划)
```

### 1.2 question —— 问句守卫

11 个词：
`为什么` `是什么` `是多少` `什么算法` `怎么理解` `怎么` `如何` `有哪些` `能否介绍` `？` `?`

1 条正则（2026-10-30 补）：
```
多少 | 几[个项天条人艘] | 哪个 | 哪一版 | 对比 | 比较 | 区别 | 差别 | 差在哪
```

判定：
```
if question and not explicit_action:  return False   # 问句，不认领
if explicit_action:                   return True
```


## 2. 层 1：拆句 `_split_compounds`

只在门判假后执行。

问句守卫（命中直接不拆）：
```
[吗么呢][?？]?$ | 是不是 | 能不能 | 行不行 | 什么时候 | 多久 | 怎么
```

切分符：
```
[，,；;。\s]+
```

启用条件：切出的段数 ≥ 2，且每段长度 ≥ 2。

合并规则：每一段都独立走完 2~8 层；**只有当所有段都拿到 route=dsl 且 dsl 非空**
才合并（`_merge_dsls`），否则整句回退到单句主链。

## 8. 层 7：向量模板

- 向量：字符 2-gram + 3-gram 计数，L2 归一
- 相似度：余弦
- 命中阈值：`VECTOR_HIT_THRESHOLD = 0.95`（几乎逐字一致才跳过 LLM）
- 命中 → `source=vector`，直接用模板里的 DSL
- 未命中 → 进层 8，top-3 模板作为 few-shot 一起送进提示词

另有 LRU 缓存（上限 1000 条，按原文精确匹配）在检索之前。

## 11. 已知问题（按严重度）

1. **门的关键词表是"裸词 in 判断"**：`不超过`、`风险优先` 这类词能把整句带走，
   句子结构完全不看。上面第四行就是活证据——用户问"差多少"，系统当成"改成高风险优先"。
   已补问句正则，但根子没动：只要命中一个词就整句认领。

   上游先执行，所以层 4 那套永远看不到这句。已对齐一部分。

   门的真假决定用哪套，而门的判据又和两套都不一致。

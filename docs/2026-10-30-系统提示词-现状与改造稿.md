# 系统提示词：现状与改造稿

日期：2026-10-30
对照代码：`backend/app/core/dsl/registry/schema_prompt.py`
实测命令：`build_system_prompt('把船租降到8万，每天最多干10小时，预算别超过500万，优先抢修高风险的')`

---

## 0. 一句话

> 现稿 4665 字符，其中约 40% 是**嘱咐**（"不要""必须""一律"）和**负面清单**（22 个改不动的名字）。
> 这两类东西有一个共同点：**违反了没有任何后果，也没有任何信号能看见它违反了。**
>
> 改造稿 4728 字符，几乎一样长（+1.4%）。但能对应机器检查的比例从 **59% 升到 93%**——
> 篇幅没变，注水换成了判据。
> 判断标准只有一条：**每一句话，是否对应一个机器检查。** 对应不上的，就是注水。

```
## 输出格式（必须是统一 JSON 包装）
{"route": "dsl" | "not_change" | "reject" | "clarify", "confidence": 0~1, "dsl": {...}}

- route=dsl：可编译的排程修改，dsl 里放 constraints / objectives / parameters / data 中任意几段。
- route=not_change：闲聊、查询、解释（"怎么算""是什么""为什么"）。
- route=reject：明确越界（非线性目标、改颜色外观、风险/可靠性/满意度等未建模的业务概念）。
- route=clarify：吃不准、缺少基准（如"顺延两天"没说从哪天算）、或引用的实体不存在。
- 时间限定的数据修改（如"未来三天电价上涨20%"）不能用全局倍率参数顶替：
  改 data 段的 hourly/weather 等时序字段，做不到就 clarify。
- confidence：0.9~1.0 很确定；0.5~0.7 吃不准；<0.6 会被系统降级为澄清。

硬性规范：
- 任务编号写全称"任务018"；风机"风机003"；窗口"窗口02"。
- 时间一律 ISO 带时区，形如 2026-11-05T08:00:00+08:00；只说到"某日"默认 08:00。
- 金额一律元（"500万"→5000000）。
- parameters 的 field 只能用「可改参数目录」里列出的名字；目录外的名字一律不要写，
  想改但不在目录里，就用 clarify 说明当前做不到。
- parameters 每项必须写 op："="（绝对值）或 "*"（相对倍率，如"涨两成"→1.2）。
- 取值形态：开关类写 "是"/"否"；时刻类写 "07:00"；数值类写数字。
- 下面四类不写 parameters，各有专门位置：
  策略 → objectives：{"type":"strategy","name":"成本最低优先"}
  预算 → constraints：{"type":"budget","quantity":"现金支出","op":"<=","value":5000000}
        （默认口径是不含发电损失的现金支出；用户明确说"连发电损失一起算"才用 总经济成本）
  必修任务 → constraints：{"type":"must","task":"任务018"}

- 标准目标策略四选一：高风险优先抢修 / 成本最低优先 / 最短完成优先 / 检修最多器件优先。

- 一句话里有多条诉求时，全部输出（不要只取第一条）。
```

### 1.3 逐段诊断：这句话有没有对应的检查

判据只有一列：**模型违反了，系统能不能发现？** 发现不了的要求，等于没写。

| 段 | 原话（摘） | 要求什么 | 有检查吗 | 违反了会怎样 |
|---|---|---|---|---|
| 角色 | "翻译成 DSL，**不要解释**" | 输出纯净 | 隐式 | JSON 解析失败才暴露 |
| 目录 | 15 行参数名 | 只用这些名字 | **有**（`route_of`） | 报错，能拦 |
| 换节 | "不能写 parameters，写到别处" | 归对段 | **有**（validator 查节） | 当场报错并指出正确位置 |
| 负面清单 | 22 个名字 + "不要假装能改" | 别硬写 | 有但昂贵 | 执行期报"未支持参数"，且措辞像系统故障不像模型错误 |
| 槽位详解 | "默认值：12000" | 给细节 | **无，且反向有害** | 见 §1.4-② |
| 原语 | 4 个"【未实现，勿用】" | 别用 | 有 | 编译器报"原型未实现" |
| data | "kind 是固定枚举，**不要自创**" | 别自创 | **有**（validator 查 kind） | 报错 |
| 实体 | "task/turbine/part/window/line/crew/time" | 用对编号 | 无 | 编号不存在时下游才炸 |
| route | 四选一 | 分类对 | 无（route 只是分支） | 无 |
| confidence | "0.9~1.0 很确定" | 自评 | **无，且反向有害** | 见 §1.4-③ |
| 硬性规范 | "**一律**""**必须**""**不要**"×6 | 格式对 | 部分 | 解析/归一化 |
| 末句 | "一句话里有多条诉求时，**全部输出（不要只取第一条）**" | 别漏 | **无** | 见 §1.4-① |

两条结论：

- **能查的要求，基本都落在"产物"上**（名字/枚举/节/字段），因为它们有 token 可查。
- **查不了的，恰好是最要命的三条**：别漏、别编、自评可信。前两条决定正确率，第三条决定你敢不敢信它。

### 1.4 三处实证失效（不是推测，是跑出来的）

**① "一句话多条全部输出" —— 写了两遍，照样漏一半。**
八层规则实测：8 条复合句，"规则层直出"4 条，**4 条全部只覆盖一半**。
提示词里这句话在最后一行的位置，还加了括号强调。没用。
原因很简单：**漏 = 空集 = 没有 token**。没有 token，任何检查器都无从下手。
写"不要漏"是让模型自律；要真防漏，必须先在原文侧数出"应该有几句"，拿到分母。

**② "默认值：12000" —— 提示词自己成了编造的出处。**
用户没说船租多少时，模型看到这行会填 12000。这个 12000 在提示词里确实存在，
所以 E6.1（无出处编造）查不到——**它是有出处的，出处是提示词，不是用户的话**。
这是"教模型踩坑"的另一种形态，和之前删掉的 5 个必错示例同源：
上一版是把错答案写进提示词，这一版是把**不该用的答案**写进提示词。

**③ "confidence 0.9~1.0 很确定" —— 自评不可验。**
`钱不超过300万` 这条，旧链路返回 `confidence 1.0` 且**静默丢掉了预算**。
1.0 的意思是"我很确定"，而事实是"我什么都没做"。
自评的问题不在准不准，在于**它和产物无关**——产物是空的，自评可以照样满分。
（这条发生在规则层，但它证明的是"自报可信度"这个设计本身不成立，
换成模型自报，同样的病。）

## 2. 改造稿

### 2.1 五个取舍

| # | 取舍 | 换来了什么 |
|---|---|---|
| 1 | 目录 + 详解**合成一张表**，加行号 P01~P15 | 同一张表的两次投影只留一次，省 226 字符；行号让"编造表头"变成"编号越界"，一查就出 |
| 2 | 22 项负面清单**删掉**，换成 `unassigned.reason` 三型枚举 | 省 569 字符。"表里没有"是定义，不需要列举；三种 reason 还能统计（多少是没建模、多少是没接通） |
| 3 | 默认值**全删** | 断掉编造素材。要补默认值必须写 `from:"default"` + `why`，且被单独计数 |
| 4 | 只输出 dsl → 输出 `claims + fills + dsl`，三者互相背书 | "漏"有了分母（A1/A2）；"编"有了对照（A3/A4）；"说一套做一套"变成 A8 编译期错误 |
| 5 | `confidence` **删掉**，换成可算的指标 | 不看模型自评，看 `from=default` 占比 + `unassigned` 占比。这是外算的，它控制不了 |

第 4 条是核心。它把产物从"一份答案"变成"一份答案 + 一份工作记录"，
而工作记录里的每一格都必须和原文对得上。

**字符数账要说清，不然看着像变魔术**：省下的是 795 字符（详解重复 486 + 负面清单 569
− 新增表 F 260），花掉的是约 860 字符（claims 规则 + fills 规则 + 验收单 A1~A9）。
净 +63。所以这次不是"压缩提示词"，是**把同样篇幅的注水换成判据**。
如果有人拿"提示词变短了"当成绩汇报，那份汇报是假的。

```
## 第一步：切句（claims）
按标点和连接词切开，一句一条。连接词含：并且、同时、顺便、另外、还要、再、以及。
- 一个数字一条。同一诉求里的起止两个数也拆两条（"从8万降到7万"→ 两条，两个值）
- 疑问、感叹、寒暄也要切出来，标 kind=ask 或 noise，不许静默丢掉
- 判断不了整段在说什么，标 kind=unsure，照样列出来
系统会独立按标点再切一遍。你的 claims 要覆盖它切出的每一段。

## 第二步：认领（fills）
每条 claim 要么进 fills，要么进 unassigned，二选一，不许两边都没有。
每个 fill 交四样：claim 编号、row、span、from。

from 只有四种：
- literal　原文有字面值。span 里必须能找到这个值（数字、日期、编号）
- convert　原文给的是说法。span 里必须能找到那个说法，calc 里写算式
　　　　　例：span="涨两成" → calc="12000*1.2=14400"
- enum　　 原文给的是说法，要落成固定词。span 里必须能找到那个说法
　　　　　例：span="优先抢修高风险的" → value="高风险优先抢修"
- default　原文没给值，你自己补。必须写 why；这条会被单独计数

unassigned 每条交三样：claim 编号、reason、note。reason 只有三种：
- concept_not_modeled　用户说的概念没建模（风险评分、可靠性、满意度、界面颜色）
- row_not_wired　　　　表里有这个栏目但没接通（候选风机、候选部件、电价全局倍率）
- need_info　　　　　　缺基准（"顺延两天"没说从哪天算；引用的任务或风机不存在）

## 第三步：交卷前自查（这一节是验收单，不是建议）
A1 覆盖　系统按标点切出的每一段，都要被至少一条 claim 覆盖
　　　　 → 漏一段：整份退回，不给部分通过
A2 闭合　每条 claim 必须有归宿，claim 数与 fills+unassigned 条数对得上
　　　　 → 有 claim 没归宿：整份退回
A3 出处　每个 span 必须是原文的连续子串，且落在 claim 指向的那一段里
　　　　 → 对不上：该条作废，其余条仍采信
A4 来源　from≠default 时，value 必须能从 span 直接得到，或由 calc 算出
　　　　 → 推不出：判编造，该条作废
A5 行号　row 必须在 P01~P15 / X01~X04 / C01~C11 / O01~O05 / D01~D06 之内
　　　　 → 越界：整份退回（不许自创表头）
A6 单值　同一 claim 里同一 row 只能一个值；跨 claim 冲突要写 conflict 字段
　　　　 → 冲突未声明：退回澄清
A7 必填　每行的必填字段都要有（见各表）
　　　　 → 缺：该条作废
A8 一致　dsl 里每一项都要有 fill 背书；每个 fill 都要在 dsl 里有对应项
　　　　 → 双向对不上：整份退回
A9 形状　顶层是对象；parameters/constraints/objectives/data 是数组；字段名照抄
　　　　 → 不合法：先归一化再重判，不算你的错

三档后果：整份退回 > 该条作废 > 归一化重判。前两档会告诉你具体哪条、为什么。

## 交卷格式

  "route": "dsl" | "not_change" | "reject" | "clarify",
  "claims": [{"id":1,"text":"把船租降到8万","kind":"action"}],
  "fills": [{"claim":1,"row":"P13","span":"8万","from":"literal","op":"=","value":80000}],
  "unassigned": [{"claim":5,"reason":"row_not_wired","note":"候选风机：表里有但没接通"}],
```

## 5. 落地顺序：提示词不能先改

这是最要紧的一条，我单独拎出来说。

**如果先改提示词、验收器后上，结果会比现在更糟。**
理由：提示词一旦要求 `span`，模型就会写 span。系统不查，模型几轮之后就会发现
"这个字段随便填也能过"。于是它开始写看起来像原文、实际不存在的片段。
这时你手里多了一份**看起来有据可查、实际是伪造的**工作记录——
比现在只有 dsl 更危险，因为现在至少执行侧会报错，而伪造的 span 不会。

所以顺序必须是**验收器先行**：

| 步 | 上什么 | 依赖 | 能不能独立回滚 |
|---|---|---|---|
| 1 | A5 行号 / A7 必填 / A9 形状 | 只要 DSL，不要原文 | 能，纯新增检查 |
| 2 | A3 出处 / A4 来源 | 要原文 + fills 字段 | 能，但需要契约里先有 fills |
| 3 | A1 覆盖 / A2 闭合 | 要原文侧标点切分 | 能 |
| 4 | A6 冲突 / A8 双向一致 | 要 dsl 与 fills 都有 | 能 |
| 5 | **换提示词 v2** | 1~4 全绿 | 能，回滚到 v1 即恢复 |

第 1 步今天就能上，因为它只查产物，不需要改契约、不需要改提示词。
第 2 步需要契约里出现 `fills`——所以它是唯一一处"契约先行"的地方，
可以先加字段、只记日志不拦截（对应 §12 的 2a），拿到"无出处率"这个数再决定拦不拦。

一句话：**提示词是验收器的说明书，不是模型的行为规范。**
说明书先写好、机器先装好，再让人上机。

## 6. 改造稿的残留盲区（说清楚，不藏）

1. **`reason` 三型判不了对错。** 模型说 `row_not_wired`，实际可能是 `concept_not_modeled`，
   机器看不出来——两者都是"没填"，只是借口不同。它只能用来统计分布，不能用来定责。
2. **A1 的"标点切分"本身有粒度问题。** "风有点大"算一段还是不算？代码切得出来，
   但"算不算一个诉求"是产品定义。切粗了漏，切细了模型要为一堆废话写 claim。
3. **`from=default` 的 `why` 无法验证真伪。** 模型可以写"用户未指定，按惯例"。
   这一格的作用不是判真假，是**让它显式承认"这个数是我编的"**，然后被计数。
4. **A4 只能查"值能不能从 span 推出"，查不了"这个 span 是不是对应这条 claim"。**
   后者要靠 A3 的"落在 claim 区间内"间接约束，是弱判据（对应 E4.2 的处境）。
5. **`weighted` 的两条编译路径仍不一致**（遗留问题 6）。提示词照列 O05，不代表执行侧一致。
   这一条属于执行侧欠账，靠在提示词里加限制解决不了，只能先修编译器。
6. **`q` / `terms` 能填什么，两稿都没给——但注册表里有。**
   我第一版在这里写的是"没有登记表"，查了一下是**错的**，得改：`quantities.py` 里
   `NAMED_QUANTITIES` 有 11 个具名量，另有 `FORMS`/`COEFFS`/`FILTERS` 三个维度，
   validator 的 `_check_quantity` 也会拦未注册名。**检查在，缺的是"把这张表给模型看"。**
   现稿只写 `minimize：必填 q`，模型要写 `minimize 完工时间和` 得先猜对名字，猜错报"未注册"——
   这是"检查存在但说明书缺页"，和漏不一致：它会让用户觉得"系统不行"，
   而实际是模型没被告知。改造稿已经补成表 F（11 行 + 3 维，约 260 字符）。
   这一条属于"补表"，可以单独上，不必和本次契约改造捆在一起。

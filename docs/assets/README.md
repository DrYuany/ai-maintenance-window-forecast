# 截图与录屏规范

README 顶部的视觉位现在是空的（只有一行 HTML 注释）。补的时候按这份要求来，
否则不如不放。

## 要拍什么

一张主图 + 一段短录屏，都围绕**同一次求解**，别拼不同状态的图。

| 素材 | 内容 | 尺寸 |
| --- | --- | --- |
| `workspace.png` | 一次**已完成**求解的工作台：左侧对话（含用户那句自然语言）、中间甘特/时间线、右侧证据面板（状态、指纹、复核清单） | 宽 1200–1600，PNG，≤ 800 KB |
| `demo.gif` | 30–60 秒：输入一句话 → 求解进度 → 结果卡 → 点开证据面板 | 宽 1000，≤ 8 MB |

## 三条硬要求

1. **不能是空状态或报错状态。** 上一版截图顶部挂着 `Failed to fetch`，被换掉了。
   截之前确认：页面无红色错误条、对话里有内容、甘特图里有任务条。
2. **一屏能看出"这是排程"。** 至少露出甘特/时间线和一条真实结论（总成本、完成项数）。
3. **别 P 数字。** 截图里的数和 `docs/sample-run/` 对不上，比没有截图更糟。

## 录屏脚本（照着走一遍就行）

1. 输入：`优先修高风险，船租上涨 20%，每天最多 2 条作业线`
2. 等求解结束，停在结果卡（别快进，让人看到进度与状态）
3. 点开右侧证据面板：模型指纹 → 复核清单 → 下载明细
4. 补一句追问：`对比方案 01 和 02`，停在差异表

第 4 步很关键 —— 它顺便证明了多方案对比是真的。

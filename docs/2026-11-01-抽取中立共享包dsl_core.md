# 抽取中立共享包 dsl_core（2026-11-01）

> 对应问题 #3 的结构性修复。来源：`源码check-list.md`。

## 结论（用户已拍板）

- **执行侧抽成中立共享包**：backend（规则优先）与 llm-first（LLM 优先）互不 import，共享执行侧单一事实源。
- **同仓库、独立目录**：不拆 git 仓库，靠目录边界隔离两个产品。

## 依赖事实（搬之前摸清的）

- `backend/app/core/dsl/` **自包含**，唯一外部依赖是 `planning_bridge.py:20` 的 `from app.core.planning_intent import PlanningRequest`。
- `PlanningRequest`（`planning_intent.py:42-77`）是纯 frozen dataclass，不依赖 `objective_catalog`；但它的 `to_payload()` 用到同文件的 `json_key()`，抽出时 `json_key` 要一起走。
- `runner.py:16` 用 `parents[4]` 定位仓库根，搬移到 `dsl_core/` 后深度从 4 变成 1。
- `llm_parser.py` 是**规则侧理解层**（规则→legacy→向量→LLM 链），不是共享执行侧，留在 backend。

## 目标结构

```
dsl_core/                      # 中立共享包（执行侧 + 共享数据模型）
  __init__.py
  planning_request.py          # PlanningRequest + json_key（自 planning_intent 抽出）
  registry/                    # parameters/primitives/quantities/data_fields/entities/schema_prompt
  validator.py
  compiler.py
  generator.py
  runner.py                    # parents[4] → parents[1]
  planning_bridge.py           # PlanningRequest 改从 .planning_request 引
backend/app/core/
  llm_parser.py                # 自 dsl/ 移出（规则侧理解层）
  planning_intent.py           # 删 PlanningRequest/json_key，改 re-export dsl_core
  ...其余 import app.core.dsl → dsl_core
llm-first/src/
  paths.py                     # 挂 dsl_core + kernel，不再挂 backend
  ...其余 import app.core.dsl → dsl_core
```

## 执行步骤

1. `git mv` 共享文件 → `dsl_core/`；`git mv llm_parser.py` → `backend/app/core/`。
2. 抽 `PlanningRequest` + `json_key` → `dsl_core/planning_request.py`，`planning_intent.py` 改为从 dsl_core re-export（保持外部 `from app.core.planning_intent import PlanningRequest` 不立即断）。
3. 修 dsl_core 内部 import：`planning_bridge` 的 PlanningRequest 改 `.planning_request`；`runner` 的 `parents[4]` → `parents[1]`；`runner` 里 `from app.core.dsl.planning_bridge` → `.planning_bridge`。
4. 修 backend 全部 import 点（~20 文件）：`app.core.dsl` → `dsl_core`。
5. 修 llm-first 全部 import 点 + `paths.py`（挂 `dsl_core`，不再挂 `backend`）。
6. 跑两边测试，修漏网。

## 验证

## 遗留（不阻塞本次）

- `llm-first/src/rulebench.py` 与 `tools.py` 里的规则侧 import（`llm_parser`/`planning_intent`）是「并排对照台」用途。真正的独立产品不该 import 对侧理解层，建议后续把 `rulebench` 抽到中立 `benchmark/` 目录。本次先维持可运行，不阻断主抽取。

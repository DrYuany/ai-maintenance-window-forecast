# 五段方案复查：骨架沿用，四处要改

复查对象是那份"护栏 → 快路 → 判读 → 校验 → 兜底 → 澄清"的五段方案。
结论：**骨架沿用，四处调整，顺序从三步并成两步。** 提示词改了三处（已改完，注入验证过）。

---

## 一、沿用的三条

这三条的证据在这轮复查里没有变，继续用。

**1. 删层 0 的门 `is_planning_request`。**
它用 30 个裸关键词判断"这句话归不归我管"，而"能认领 ≠ 读得懂"的漏洞主要就在这里。
`钱不超过300万` 被路由词认领、预算正则不认"钱"、返回默认方案 conf 1.0——起点就是这道门。

**2. 规则降为三个岗位，不再有整句认领权。**
这是整个方案里最正确的一条。今天的实测仍然支持它：221 条库里规则层直出 68，
旧编译器 45，两者重叠 37，都不中 145。两套系统在同一批能力上重复维护，且没有测试比对过它们。

**3. 先加判据、再动架构。**
这条也对，只是判据的载体要换。原方案用"完全消费"（原文每个实词段都被正则 span 覆盖）——
那是给规则层用的判据。现在有了 A1~A10，判据升级成"每条 action claim 都有归宿"，
对规则和模型都适用。**判据通用之后，两个产品才能用同一把尺子比。**

## 二、四处调整

### 调整 1：不要上 8 个 route，上 4 个 + 两个子字段

原方案列了 8 个 route，理由是"一个 route 存在的唯一理由：它通向不同的代码"。
这个理由本身对，但**当时没查代码里到底有几个执行器**。实测：拿 8 个 route 名去喂当前契约，

| 方案要的 route | 实际返回 | |
|---|---|---|
| modify_plan | clarify | 被改写 |
| modify_data | clarify | 被改写 |
| query_plan | clarify | 被改写 |
| compare | clarify | 被改写 |
| explain | clarify | 被改写 |
| chitchat | clarify | 被改写 |
| reject | reject | 保留 |
| clarify | clarify | 保留 |

**8 个里 6 个会被静默改写成"请澄清"。** 原因在 `llm_parser.py:649`：
`dsl = payload.get("dsl") if route == "dsl" else None`，只要 route 不是 `dsl`，
dsl 就是 None，然后 `:659` 判 `not isinstance(dsl, dict)` → 返回 clarify。

这就是"提示词教模型踩坑"的又一个版本：模型判对了，系统把它的答案改成"我没听懂"。

**改成：4 个 route + `kind` / `about` 两个子字段。** 8 种意图一个不少地覆盖，但只有一条通往执行器：

| 意图 | 现在怎么表达 | 谁执行 |
|---|---|---|
| 改参数/约束/目标 | `route=dsl` + `parameters`/`constraints`/`objectives` | 同一条编译路径，按段分派 |
| 改底层数据 | `route=dsl` + `data` | 同上（段名就是分派键） |
| 查事实 | `claim.kind=ask, about=fact` | 先记录，暂无执行器 |
| 比两版 | `claim.kind=ask, about=diff` | 先记录，暂无执行器 |
| 讲机制 | `claim.kind=ask, about=reason` | 先记录，暂无执行器 |
| 闲聊 | `claim.kind=noise` | 对话层 |
| 做不到 | `route=reject` | 有执行器 |
| 说不清 | `route=clarify` | 有执行器 |

`about` 是**只记录、不拦截**：它回答的问题是"这三种读请求到底各占多少"，
等有了数再决定给谁建执行器。这正是"先测再建"，不是先建再发现没人用。

### 调整 2：快路实测是缓存，不是快路

原方案说"向量相似度 ≥ 0.95 且数字序列一致 → 复用模板 DSL"。
我实跑了三组：

| 实验 | 结果 |
|---|---|
| 改一个任务编号（短句） | 相似度 0.72，**不命中** |
| 改一个任务编号（长句） | 0.89–0.90，**不命中** |
| 221 条评测句跑一遍 | 命中 14 条，**14 条全部逐字相同** |
| 70 条对抗句 | **0 条命中** |

结论有两条，都很硬：

1. **不命中 0.95 的原因不是"数字对账"，是阈值本身。** 16 条模板 + 0.95 余弦，
   改一个编号就掉到 0.9 以下——阈值在替数字校验干活。所以原方案担心的"把任务003带成005"
   在当前配置下不会发生，但代价是：
2. **它只对逐字重复的句子生效。** 14/221 = 6.3%，且全是原句。而 `_PARSE_CACHE`
   已经在内存里缓存逐字重复的句子了。**向量层 = 带额外步骤的缓存。**

**改成：删掉向量层，保留缓存。** 五段变四段。如果以后模板库涨到 200+ 条，
再来讨论"要不要一个真的快路"——那时阈值必须降到 0.8 以下，而那时"数字对账"
才真的有用，因为 0.85 的相似度确实可能带着旧编号。

### 调整 3：护栏不能只是"前移到最前面"，要改判据

原方案说"护栏（规则，只否决）永远先跑"。方向对，但直接前移会造出反向 bug。
现在 `_parse_core` 的顺序是 `parse_by_rules`(860) → `_classify_not_change_only`(866)，
把非改类判定往前挪一位，就变成"任何含'为什么/多少/对比'的句子都归闲聊"：

| 句子 | 规则层 | 非改类判定 |
|---|---|---|
| 把船租降到8万，为什么这么贵 | None | **not_change** |
| 预算改成350万，跟上一版差多少 | None | **not_change** |

这两句里都有一半是真的改动。前移之后，整句被当闲聊，改动丢失且不报错——
**和"复合句直出只覆盖一半"是同一种病，只是换了方向。**

注意上一轮"经济优先和风险优先差多少"能判对，靠的是给 `planning_intent` 补了问句守卫词，
不是靠顺序。补守卫词能救一个句子，救不了这一类。

**改成：护栏只判"结构上非法"，不判"是不是排程"。** 具体三类：
非线性（平方/开方/取最大）、越界操作（改颜色、改代码、改数据库）、明显矛盾（同一个参数两个值）。
这三类命中就 reject，不问模型。**"这句话算不算改动"不进护栏**，交给模型 + A1/A10 判。

理由：A10 已经能机器判死 `not_change` 里藏 `action` 的情况。有机器判据的地方，
不需要再用正则猜一遍——这正是"同一件事被抄三遍"的老毛病。

### 调整 4：兜底必须过同一套验收单

原方案说"兜底（33 条规则），但必须完全消费才准直出"。
这条现在要收紧成：**兜底产出必须过 A1、A2、A5、A8、A10，一条不能少。**

理由是对比实验的有效性。如果 LLM 路径要过 10 条验收、规则兜底只过"完全消费"一条，
那么"LLM 主导版更严"这个结论是必然的，不是因为 LLM 更好，是因为裁判不同。
**两条路径过的检查必须是同一套，差异才归因于理解层。**

顺带一个直接后果：`把船租降到8万，为什么这么贵` 交给兜底规则，
规则层今天返回 None（见上表），走不到"完全消费"——也就是说这条兜底本来也不存在。
33 条规则的真实覆盖就是那 68 条直出的句子，别指望它接住复合句。

### 顺序：三步并成两步

原方案：① 加完全消费判据 → ② 三道校验关 + 数字对账 → ③ 动顺序、删旧编译器。

现在 ① 和 ② 是同一件东西：`verify.py`（A1~A10）。"完全消费"是 A1 在规则侧的特例。
所以：

1. **写 `verify.py`，用 18 条错误分类学案例做回归**（这一步产出的是尺子，两个产品共用）
2. **接进两条路径，都过同一套检查，先只记日志不拦截**（拿到基线）
3. 看基线决定要不要开拦截、要不要删旧编译器

第 3 步现在**不在本轮范围**：`backend/` 是对比基线，删了就比不出来了。
原方案说"先保留旧编译器、等 LLM 稳定再删"——这个"再删"要挪到对比实验结束之后。

## 三、提示词改了三处（已改，测试盯住了）

复查时发现提示词自己有三处矛盾，都是上一版我写的，跟方案无关，但必须先修，
否则 `verify.py` 写出来会照着错的定义判。

**B1：`kind` 两套枚举。** 第一步教的是 `kind=ask`/`noise`/`unsure`，交卷示例写的是
`kind:"action"`。同一个字段两种取值，模型只能猜，而且没有任何检查会红。
→ 统一成 `action`/`ask`/`noise`/`unsure` 四值表，并说明哪几种需要归宿。

**B2：A2 把 `not_change` 锁死了。** 原文"claim 数 = fills + unassigned 条数"，
而 `not_change` 规定"没有 fills 但 claims 照样要切"——于是**任何 not_change 答案都过不了 A2**。
契约自己把自己判死。
→ A2 改为"每条 `action` claim 都有归宿；`ask`/`noise`/`unsure` 不需要"。

**B3：`not_change` 能吞掉改动。** 这正是上面调整 3 里那两句的病。
光写"记得两种都切出来"没用——那是嘱咐，没人查。
→ 新增 A10：「`not_change` 时不许有 `action` claim」。

三处都加了测试，并用注入旧写法验证过测试会红：

```
注入旧写法 → 2 failed, 16 passed
  FAILED test_not_change_cannot_swallow_an_action
  FAILED test_every_action_claim_needs_a_home
还原     → 18 passed
```

提示词 7740 → 8187 字符（+447）。多的部分全在 `kind` 表和 A10，两处都对应检查。

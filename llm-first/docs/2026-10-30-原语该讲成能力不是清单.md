# 原语该讲成「能力」，不是「清单」

日期：2026-10-30
对应代码：`llm-first/src/prompt.py` 的 `capability_block()`
触发：你说"把元语塞给大模型，大模型好像不知道拿那个东西能干嘛"

---

## 1. 你指出的问题，先确认它是真问题

旧稿的原语块长这样（实测原文，670 字符）：

```
## 约束原语（constraints）
- must：必填 task
- exclude：必填 task
- at_most_one：必填 tasks 【未实现，勿用】
...
- linear：必填 terms、op、value
co_occur 的 mode 取值：same_day/diff_day/same_window/... ；当前实现 ['diff_day', 'same_day']
## 目标原语（objectives）
- strategy：必填 name
- minimize：必填 q
...
```

一个模型从这里能得出的唯一结论是：**"有 11 个（实际列了 15 个）可选项，每个要填几个字段。"**

它得不出的是：**这 11 个东西合起来，构成了"我能改什么"的全部空间。**

差别不是措辞。是它会不会去组合。

- 以为这是清单 → 用户说"任务001和002必须同一天" → 在表 A 里找不到 → 放弃或编一个近似的
- 知道这是能力 → 同上 → 想起来 `co_occur same_day` → 拼出来

**旧稿把"零件"给了，把"零件能拼什么"扣着。** 这不是文风问题，是信息缺失。

---

## 2. 缺的是三层，不是一句解释

补一层不够，三层缺一不可：

| 层 | 缺什么 | 不补的后果 |
|---|---|---|
| 第一层 分类 | 参数（旋钮）和原语（积木）**性质不同** | 模型把两者当同类，都按"查表有没有"处理 |
| 第二层 用途 | 具体能拼出什么，要**例子**，且必须是"表 A 没有但能拼"的 | 模型不知道边界在哪，只会照抄表 A |
| 第三层 边界 | 拼不出什么，**为什么**拼不出 | 模型瞎试，拿 `cardinality>=1` 顶"全部" |

只补第二层（多给几个例子）不够：
没有第一层，模型会以为这些例子是"特例"，记住例子而不理解规则；
没有第三层，模型遇到边缘诉求会硬凑——这比说"做不到"更糟，因为凑出来的约束会真的被执行。

---

## 3. 怎么补的

### 3.1 第一层：给两类东西起名字

```
表 A 是拧好的旋钮：15 个，每个都有业务名字。用户说"船租""工时"，你直接拧。
                 拧到表外就是没有——这是旋钮的性质，不用纠结。
表 C 是积木：11 种，没有业务名字，只有形状。它们能拼出表 A 拼不出的东西。

一句话区分：
  表 A 回答「这个词有没有对应的参数」
  表 C 回答「这句话能不能被表达」
```

"旋钮/积木"这个比喻的作用不是好懂，是**让两类东西在模型心里分到两个抽屉**。
旋钮的失效方式是"拧到表外"，积木的失效方式是"拼不出形状"——两种失效的应对完全不同。

### 3.2 第二层：9 个例子，全部是"表 A 没有"的

| 用户说 | 怎么拼 |
|---|---|
| 任务001和任务002必须同一天做 | C04 `co_occur{same_day}` |
| 任务001和任务002别排同一天 | C04 `co_occur{diff_day}` |
| 先修任务001，隔两天再修任务002 | C03 `precedence{gap:2}` |
| 任务018不能晚于11月8日 | C07 `deadline` |
| 11月3日到5日别开工 | C09 `forbidden_dates` |
| 把任务001固定到2号船 | C05 `fix` |
| 至少要修完5个 | C06 `cardinality{>=,5}` |
| 整体越早收工越好 | O02 `minimize{q:"最后完工时间"}` |
| 总成本压到最低 | O02 `minimize{q:"总经济成本"}` |

**每一条都刻意选表 A 里没有对应参数的。** 如果例子全是"用 P13 改船租"，
模型学到的是"查表"，不是"组合"。例子的选择本身就是教学内容。

后面接一句判断标准：

> 这句话是不是在限制「选哪些任务、什么时候做、怎么排、花多少钱」？
> 是 → 一定能落到某块积木上，或者几块的组合。
> 不是 → 才叫做不到。

这句是让模型**自己判断**，不是让它背例子。例子会忘，判据不会。

### 3.3 第三层：边界，而且要说出"为什么"

```
C11 linear 能装任意线性式，可式子里的每一项都必须来自表 F。
所以真正表达不了的是下面三类：

1. 「全部」这种量词。只有 C06「至少 N 个」，没有「全部」。
2. 量目录里没有的单项。有"现金支出"这种合账，没有"船租"这个单项。
3. 非线性的东西。比值、平均数、最大值、方差、"均衡"。
```

注意第一句的修正：**边界不在"线性"这个词上，在"量目录"上。**

我一开始想写"凡是能写成线性式的都能装"，查了一下是错的：
`linear` 的每一个 term 都要引用一个量，而量目录只有 11 个具名量 +
（2 种形式 × 7 种系数 × 7 种过滤）。**能表达 = 原语 × 量目录，是乘法不是加法。**

如果写成"线性式都能装"，模型就会去拼一个 `terms` 里有"船租"的式子，
然后校验器报"量未注册"——**这又是提示词在教模型踩坑**。

## 4. 补的过程中撞出两个真缺口（能力账，不是提示词问题）

写第三节的时候想举"高风险的必须全修完"，发现举不出来。查完确认这两条现在真做不到：

| 诉求 | 卡在哪 | 补法 |
|---|---|---|
| "高风险的必须全修完" | 只有 `cardinality`（至少 N 个），没有"全部"这个量词 | 加 `must_all(filter)` 原语，编译成 `Σx_i == \|filter\|` |
| "船租和人工加起来不超300万" | 量目录没有"船租"单项，只有"现金支出""总经济成本"合账 | 在 `COEFFS` 加 `ship_rent`，或加一个具名量"船租" |

这两条**必须写进提示词让模型知道该拒**。不写，它就会拿 `cardinality>=1` 顶"全部"——
旧版实测就是这么错的：`成本压到最低，但高风险的必须全修` →
`cardinality{severity:高, op:">=", value:1}`，判 E4.3（近似栏目顶替）。
这条记录在 `backend/eval_cases/error_taxonomy.py` 的"真实观测到的错误形态"分组里。

这是本轮最有价值的副产物：**为了讲清"能干什么"，被迫把"干不了什么"也查了一遍。**

## 5. 顺带删掉的一处坏讲法

旧稿有这么两句：

```
- 标准目标策略四选一：高风险优先抢修 / 成本最低优先 / 最短完成优先 / 检修最多器件优先。
  用户说"按风险来排""重视安全"→高风险优先抢修；"省钱""成本优先"→成本最低优先。
```

这是**关键词映射**，不是讲用途。实测后果：

> `经济优先和风险优先差多少` → 被映射成 `strategy=高风险优先抢修`

这句是在**问两者差多少**，不是在下指令。但提示词教的是"看到'风险'→选高风险优先"，
模型照做了，于是系统把一个比较句执行成了修改。

新版把这两句映射删了，只留四个策略名。理由：

- 策略名本身自解释（"高风险优先抢修"不用解释也知道是什么）
- 关键词映射会把"理解这句话在要求什么"降级成"匹配关键词"
- 而比较句、假设句、否定句里都会出现"风险"二字

删掉映射后，模型必须理解整句才敢选。这正是我们想要的。

## 6. 这个补法的代价，说清楚

| | 旧稿 | 新稿 |
|---|---:|---:|
| 原语块 | 670 字符 | 1303 字符（积木段） |
| 整个提示词 | 4665 | 7740 |

长了 66%。这不是"顺手加了一段话"，是**从"字段清单"变成"岗位手册"**的必然成本：

| 段 | 字符 | 干什么 |
|---|---:|---|
| 岗位（含系统背景） | 356 | 告诉模型它在整条链路的位置 |
| 工具性质（积木段） | 1303 | 本轮新增的核心 |
| 干活步骤 | 1361 | 切句 / 认领 / 交卷 |
| 验收单 A1~A9 | 891 | 机器怎么查 |
| 交卷格式 | 649 | 骨架 |
| 参考表 A~F | 3170 | 附录，查的，不是读的 |

判断这 7740 字符值不值，还是那把尺子：**每句话是否对应一个机器检查。**
积木段的 1303 字符对应的检查是 A5（行号在表内）+ A8（dsl 与 fill 双向一致）——
如果模型不知道"表 A 没有也能拼"，它就会在 A5 上反复越界，或者干脆不填。
**这一段是在减少 A5/A8 的失败率，不是在增加模型的记忆负担。**

## 7. 还没解决的

1. **"旋钮 vs 积木"这个二分是否真的被模型接受，要实测。** 现在是设计判断，
   得用同一批 case 跑两版提示词比诉求覆盖率和越界率。没有这个数，这一段只是好看。
2. **9 个例子覆盖不到"组合"**（例子里都是单原语）。真实诉求常要 2~3 块拼，
   比如"先修高风险的，隔一天再修其余的" = `cardinality` + `precedence`。
   要不要加组合例子，等实测看模型会不会自己合。
3. **边界第 2 类（量目录没有单项）会随量目录变化。** 现在写死"没有船租"，
   将来加了 `ship_rent` 就得改提示词。这条目前靠 `self_check()` 之外的人工记忆，
   应该改成从 `quantities.py` 自动生成"有哪些量、哪些合账拆不开"。

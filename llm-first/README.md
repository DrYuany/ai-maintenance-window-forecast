# LLM 主导版（llm-first）

> 这是一个**新产品**，不是旧版的升级。
> 旧版（规则主导）原封不动留在 `../backend`，两边共用同一个执行侧，并排对比。
> 打开 http://127.0.0.1:8011 就是一页双栏的对照台。

---

## 1. 为什么另起一版，而不是改旧的

规则主导和 LLM 主导不是"同一件事的两种实现"，是两种产品判断：

| | 规则主导（`../backend`） | LLM 主导（本目录） |
|---|---|---|
| 第一性假设 | 用户说法可穷举，穷举得越多越准 | 用户说法不可穷举，但**模型的错法可穷举** |
| 谁先说话 | 正则先拦，拦不住才问模型 | 模型先读全句，护栏只做结构性否决 |
| 能力边界 | 15 个参数白名单 + 硬编码句式 | 原语 × 量目录的组合闭包（见 §3） |
| 产物 | 一份 DSL | 一份 DSL + 一份可核对的工作记录 |
| 怎么保证不错 | 写更多规则、补更多句式 | 验收器逐条核，核不过整份退回 |
| 失败方式 | 静默丢诉求，返回 conf 1.0 | 显式标 `unassigned`，退回或澄清 |

硬塞进一套代码里，两边的假设会互相污染：规则层的"能认领就算读懂"
会传染给模型层，模型层的"依据可查"又要求规则层改契约。
**分开两个目录，比在一个文件里加 if 干净。**

## 2. 架构：只换理解层，不换执行层

```
用户一句话
   │
   ├─ 规则主导：正则/句式 → 编译 → CP-SAT
   │
   └─ LLM 主导：护栏 → 缓存 → 模型切句+认领 → A1~A14 全检 → 编译 → CP-SAT
                                              ↓ 不过
                                          退回重试一次 → 再不过 → 澄清
```

**编译器和求解器是共用的**（`app/core/dsl/compiler.py`、`maintenance-milp-modeler/`），
本目录一行都不复制。理由：要比的是"理解得对不对"，如果两边执行侧也不同，
差异就说不清是谁造成的。

**没有规则兜底，这是有意的。** 兜底会让"LLM 主导版"变成混合体，比不出理解层的差异；
而且上一版实测 33 条规则的真实覆盖就是 68 条直出句子，接不住复合句——
拿它兜底，等于把"静默丢一半"重新放回来。验收不过时，正确动作是承认没读懂。

**没有"快路"。** 原方案有"向量相似度 ≥0.95 就复用模板"。实测：改一个任务编号，
相似度掉到 0.72–0.90，不命中；221 条评测句命中 14 条，**14 条全部逐字相同**；
70 条对抗句 0 命中。这个阈值只在逐字重复时生效，而逐字重复本来就有缓存。
**快路 = 带额外步骤的缓存**，删掉。

## 3. 能力边界：原语是积木，不是清单

这是本版和旧版最本质的差别，也是旧版提示词最大的表达缺陷。

旧版把 11 个约束原语列成一张表，每条只写"必填哪些字段"。
模型看完只知道"有这么 11 个词，每个要填几个字段"，
**不知道这堆东西合起来意味着"凡是能用它们拼出来的诉求，我都能改"**。

```
能表达 = 11 种约束原语（含 C11 linear 兜底）
        × （11 个具名量 + 3 种形式 × 7 种系数 × 7 种过滤）
```

注意这是乘法，不是加法。所以边界不在"线性"这个词上，在**量目录有没有那一项**上。
八个真实缺口（不是模型笨，是能力没接）——前四条是"表 A 里找不到这个词"，
后四条是"这句话限制了别的东西"：

| 诉求 | 为什么现在表达不了 |
|---|---|
| "高风险的必须全修完" | 只有 `cardinality`（至少 N 个），没有"全部"这个量词。缺 `must_all(filter)` |
| "船租和人工加起来不超过300万" | 量目录里没有"船租"这个单项（只有 `现金支出`/`总经济成本` 合账），拆不开 |
| "只排风机003的任务" | 没有"筛整份计划"的原语；`filter` 只在单块约束内部筛量。`候选风机` 已登记未接通 |
| "不是越早越好，要均衡" | 比值、方差、最大值这类非线性，`linear` 装不下 |
| "明天只有3个人能出海" | 人员/船/作业线都是**全程**参数，没有"只在某天不同"。写成全程会把一天的事变成整月的事 |
| "删掉任务012" | 那是改输入台账，不是改排程。`exclude` 是"这次不修"，不等于"删掉" |
| "高严重完成数占六成、成本占四成" | 表 D 没有加权求和。`weighted` 登记了但编译器不认，交给 A14 拦 |
| "同一条船干完一个活要歇2小时" | 模型里只有"风机间转移"（换风机的路上），没有"活儿之间必须空多久" |

五到第八条尤其要盯：**它们都能编译过、也能求解，只是结论是错的。**
前四条对着空字段会当场报错，后四条不报错——所以提示词里每一种都写清了
"不要拿什么近似顶替"，A13/A14 再把最常见的两种顶法判死。

## 4. 判据 A1~A14

| 编号 | 判据 | 不过会怎样 |
|---|---|---|
| A1 覆盖 | 系统按标点切出的每一段，都被至少一条 claim 覆盖 | 整份退回 |
| A2 闭合 | 每条 `action` claim 都有归宿（fills 或 unassigned） | 整份退回 |
| A3 出处 | 每个 span 是原文连续子串，且落在它指向的那条 claim 里 | 该条作废 |
| A4 来源 | 值能从 span 得到或由 calc 算出；**不许留相对时间词**（"明天"不是值） | 判编造，该条作废 |
| A5 行号 | `row` 在行号目录内（P/X/C/O/D 五组，由注册表算出来） | 整份退回 |
| A6 单值 | 同一 claim 里同一行只能一个值（见下面三条例外） | 必须走 clarify |
| A7 必填 | 每行必填字段齐全（必填表由 validator 决定，不手抄），退回消息指名缺哪个键 | 该条作废 |
| A8 一致 | dsl 每项有 fill 背书；每个 fill 在 dsl 里有对应项 | 整份退回 |
| A9 形状 | 结构合法、枚举合法；**日期字段里必须是日期** | 整份退回 |
| A10 不改 | `not_change` 不许藏 `action`；`reject` 每条都要给理由 | 整份退回 |
| A11 方向 | 说「不超过/最多」→ op 必须 `<=`；说「至少/不低于」→ `>=` | 方向反了 → 整份退回 |
| A12 不轻拒 | `reject` 时原文有表内线索词 → 只记线索 | 不拦，只提示 |
| A13 量词 | 说「全部/所有/全修」时不许写成 `cardinality{">=",1}` | 拿近似顶替 → 整份退回 |
| A14 可执行 | `weighted` 这类"能过校验、编译器却会抛错"的原语不许出现 | 整份退回 |

四态：`pass` / `fail` / `unclear` / `na`。**`unclear` 只记日志不拦截**——
把"我判不了"说成"你错了"，一条假警报就足以让人关掉整套验收器。

### A6 的三条例外

"一行一个值"是对的，但有三类填法天生就不是一行一个值。判错之前先看它是哪一类：

| 情形 | 例子 | 为什么不算冲突 |
|---|---|---|
| 原语本身装一串 | `lexmin` 的 `stages` | "先最小化A再最小化B" 天然在同一行填两条 |
| 同一条补丁的两半 | `{part,at,quantity:2}` + `{part,at,blockBefore:true}` | 一句话切成两条 claim 各填一半字段 |
| 它不是 | 同一个键填两个不同的数 | **这条照旧判死** |

名单从注册表算（`required` 里含 `stages`/`weights` 的原语），不手抄。

### A4 的两处口径不一致，是故意的

| 比什么 | 认不认中文数字 | 为什么 |
|---|---|---|
| 一条 fill 的 span 对它的 value | **认** | 用户说"两条"，就是说了 2；不认等于没听见 |
| 整句话对整套 DSL（数字对账） | **不认** | 范围太宽，"同一天""一小时"都会被读成数，上线当天冒出三条假警报 |

编译器报错也算不过（`op` 写错、`terms` 形状不对），会和 A1~A14 一起进退回消息——
否则模型永远不知道自己错在哪（实测：A 全过、编译器一句"非法运算符 '='" 就退了）。

## 5. 数字对账：两边唯一完全共用的判据

`audit_numbers(原文, dsl)` 不需要 claims/fills，所以规则侧也能跑：

- 原文有、DSL 没有 → 丢话
- DSL 有、原文没有 → 编造或默认值
- **route 不是 `dsl` 时整个对账不适用**：没交出 DSL 就没有"丢"这回事。
  这条是跑批跑出来的——正确拒绝的一句话也被记了"丢数"，比漏报更伤。

三类"原文的数和 DSL 的数本来就该不同"，硬对账只会造出那种**每次都对**的假警报，
而每次都对的警报，看的人三天就学会无视整列：

| 情形 | 例子 | DSL 里该出现的是 |
|---|---|---|
| 百分比 | 上涨20% → `*1.2` | 1.2，不是 20 |
| 12 小时制 | 下午6点 → `18:00` | 18，不是 6 |
| 增减量 | 船少一条（现值 3）→ `=2` | 2，不是 1 |

实测 `人工单价涨到200，任务003最晚11月9日修完`：
LLM 侧交 2 项、丢 0 个；规则侧这一句**交不出 DSL**（它只认下两段里的第一段），
退到最后兜底的旧规划编译器时，只交出 `200`，**把 3、9、11 三个数字一起丢了**。

另一句 `任务001和任务002不要同一天做，钱不超过300万` 规则侧能交（拆段合并），
但它顺手塞了 `strategy=成本最低优先`、`mode=分层`、`solver.seconds=300`——
**用户没说的东西，它替你说了。**

## 6. 目录

```

├── src/
│   ├── prompt.py     系统提示词（表 A~F 全部由注册表生成，不手抄）
│   ├── rows.py       行号目录 P/X/C/O/D（提示词与验收器共用一份）
│   ├── segment.py    系统切段（A1 的分母）+ 连接词表（提示词从这里取）
│   ├── contract.py   产物形状、枚举、键名归一化
│   ├── verify.py     A1~A14 + 数字对账
│   ├── guardrail.py  结构性护栏（只否决，不认领）
│   ├── client.py     DeepSeek（JSON 模式，标准库 urllib，无额外依赖）
│   ├── pipeline.py   护栏 → 缓存 → 模型 → 验收 → 退回重试 → 澄清
│   ├── context.py    会话基准（今天几号 + 参数现值 + 窗口起止）+ 相对时间换算

│   └── paths.py      把 ../backend 与求解内核挂进 sys.path
├── eval/cases.py     分层评测集：67 条手写（每条写清在证明什么）+ 221 条 backend 压力集
├── tests/           118 条：提示词结构 + 验收判据 + 切段 + 数字对账 + 规则侧边界

├── web/index.html    单页双栏对照台
├── scripts/          bench_compare.py（两侧对照）+ bench_stability.py（跑多遍看抖动）
│                     + bench_suite.py（跑评测集，--repeat 连跑看抖动）
│                     + worker.py（求解子进程）
├── server.py         FastAPI :8011
└── docs/
    ├── 对照结果.md            十句话两边各读一遍（一次快照）
    ├── 稳定性.md              同样十句各跑 5 遍的分布
    ├── 评测-core.md           67 条分层评测（默认连跑 3 遍，报稳过/稳错/抖动）
    ├── 评测-backend.md        221 条压力集（按原标签）
    ├── 2026-10-30-落地记录.md 施工日志：十个坑 + 实测数
    ├── 2026-10-30-五段方案复查.md
    └── 2026-10-30-原语该讲成能力不是清单.md
```

## 7. 怎么跑

```bash
# 1. 配 key（不要提交，.gitignore 已挡）
echo 'DEEPSEEK_API_KEY=sk-...' > llm-first/.env

# 2. 起服务，打开对照台
cd llm-first
"D:/env/conda/2024/python.exe" server.py        # → http://127.0.0.1:8011

# 3. 只看提示词
"D:/env/conda/2024/python.exe" src/prompt.py            # 打印全文
"D:/env/conda/2024/python.exe" src/prompt.py --stats    # 分段篇幅

# 4. 回归
"D:/env/conda/2024/python.exe" -m pytest tests/ -q
"D:/env/conda/2024/python.exe" scripts/bench_suite.py --suite core --repeat 3 --save   # 67 条 ×3
"D:/env/conda/2024/python.exe" scripts/bench_suite.py --suite backend --save           # 221 条压力
"D:/env/conda/2024/python.exe" scripts/bench_stability.py -n 5 --save                  # 十句 ×5
"D:/env/conda/2024/python.exe" scripts/bench_compare.py --save
```

改完提示词先跑 bench，再去页面上看观感——顺序反了，就会拿"看起来不错"当验证。

**`--repeat` 值得默认开着**：单跑一遍会把"这次读错了"和"这句话本来就不稳"
混成一个数字。连跑三遍报出"稳过 / 稳错 / 抖动"三类，抖动那几条单独列出来——
它们的修法和"理解错"完全不同（前者通常要改判据的稳定性，后者才改提示词）。

当前实测（67 条 ×3 遍）：稳过 65，稳错 0，抖动 2。
221 条压力集：**过 200**，剩下的 21 条里 19 条是"route 不同、其余都对"的口径分歧，
大多落在上面那八个能力缺口上（按严重级别批量截止 6 条、加权目标 4 条）。

规则主导版的完整界面还是原来那套：`npm run dev`（:3000）+ 后端（:8010）。
对照页右上有它的入口。

## 8. 已知边界（不藏）

1. **`about` 只记录不拦截**（fact / reason / diff）。这三个读请求没有执行器，
   先统计占比，再决定给谁建。写错了不会有任何后果。
2. **`linear` 的量与 filter 有真边界**：量只能取表 F 具名量或三种形式；
   `filter` 只有 task/turbine/part/severity/window/day/line 七个键。
3. ~~相对时间没有基准~~ **已修**：`src/context.py` 注入"今天几号"。
   "明天风大，先别出海"现在一次落到 `2026-10-31`，不用再问用户；
   算不出来的（"下周""月底"）明确退回澄清，不猜。
   同一样东西还有两份现值表：参数现值（"船少一条"要它）和窗口起止（"延后两天"要它）。
4. **提示词 14718 字符**，比规则主导版的 4665 长两倍多。长的部分全在
   "积木能拼什么/边界在哪"和 A1~A14 验收单——两处都对应机器检查，不是嘱咐。
   `python src/prompt.py --stats` 会分段报字数，并顺带报静态前缀占比。
5. **段落顺序有一条硬规矩：逐字不变的排前面，会变的排最后。**
   LLM 的提示词缓存只认前缀，开头一动，后面全部重新计费。
   "今天几号 + 现值"原先排第 2 位，把它后面一万三千字全拖着每天变；
   挪到末尾之后，静态前缀从 356 字符提到 13332（占比 2% → 91%）。
   `prompt.SECTIONS` 的第二列就是这条规矩，`prompt.prefix_check()` 盯着它——
   往静态段里混一个跟着日期走的值，测试会红。
6. **规则侧不交工作记录**，所以 A1~A4、A8 对它无从验收。这不是判它错，
   是它没有这项产物。两边可比的是：编译校验、数字对账、以及它认出了什么。
7. **"能编译"不等于"意思对"**。`只排风机003的任务` 曾被写成
   `count(filter=风机003) == 1`——"正好完工一个"，不是"只排003"，而 A1~A13 全过。
   把边界写进提示词后它自己改成了 `reject`，但这靠的是模型听话，不是机器判据。
   要机器判，得把 claim 文本和 DSL 语义对齐——这是下一步真正值钱的东西。
8. **`task: "*"` 是一份完全空转的约束**。LLM 侧把"完工时间不能晚于11月20日"
   写成 `deadline{task:"*", time:...}`：校验不报错、编译不报错、求解照出计划，
   但 `resolve_task("*")` 返回 `None`，候选集永远匹配不上，
   `_add_subset_zero` 拿到空列表直接 `return`——**那条日期限制一个字都没进模型**。
   比上面第 7 条更狠：第 7 条至少真的改了模型（只是改错），这条是改了个寂寞。
   A1~A14 目前一条都拦不住（判据消息会报"全都通过了"）。
9. **同类扮演**：上面那类"能编译但意思错"，目前只对**八类已知缺口**中的
   A13（"全部"被顶成 `>=1`）和 A14（`weighted` 没编译器）有机器判据，
   其余六类还是靠提示词劝阻。每加一条这样的判据，都要先想清楚
   "它会不会反过来冤枉正确的写法"——前面踩过两次（A1 的连接词、A6 的 lexmin）。
